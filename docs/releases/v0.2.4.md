# Hutch v0.2.4

A clearer view of each box's work, and fixes found setting up a fresh pair of machines. See [the TUI](https://github.com/mouizahmed/hutch/blob/main/docs/tui.md).

## New

- **Line counts in the sidebar.** A box with work no remote has, committed or not and new files included, shows its lines, like `+17 −1`. A box with none shows nothing.
- **A clearer Git view.** A summary line of files and lines changed and commits not pushed; each file's lines; the commits not yet pushed, listed under the files; and an empty state that tells "nothing uncommitted" from "clean". The task diff shows its totals and sets off each file.

## Fixes

- `hutch user sync` leaves out an agent's gateway settings when the gateway is on this computer, such as Claude's `ANTHROPIC_BASE_URL=http://127.0.0.1:8317`, which a box can't reach. It says what it left out, and boxes use their own login. An adapter declares these fields with `gateway`.
- Machines are named by the SSH host you set them up or add them as, like `hutch-vps2`, instead of the lead taking the server's hostname. Running `hutch setup <ssh-host>` again renames an existing lead.
- `hutch new` outside a project boots the base image, instead of failing with `no box "base"`. In a project with no template, the error now suggests `hutch new --image base`.
- In the Git view, a diff line with tabs no longer runs past the pane.
- The TUI docs say how to switch projects: `[` and `]`, clicking a tab, and `+` for closed projects and other checkouts.

## Upgrading

`hutch machine upgrade` upgrades the lead, then every worker. Running boxes keep running; their line counts appear after their next cold boot, or in boxes made from a template version built after the upgrade.
