# Hutch v0.2.3

Fixes for backups and canceling commands. See the [v0.2.2 notes](https://github.com/mouizahmed/hutch/blob/main/docs/releases/v0.2.2.md) for what's new in v0.2.

## Fixes

- Garbage collection deletes a backup chunk only if it hasn't changed since it was listed, so a backup that refreshes an old chunk while a sweep runs keeps it. Before sweeping, Hutch checks that the bucket honors conditional deletes, and refuses to sweep if it doesn't.
- A restore that fails partway, for example on a chunk it can't read, leaves the machine's directory as it was, so it can be run again.
- Canceling a command that is waiting on a machine stops the wait at once, instead of hanging until the machine answers.
- Config values of `nan` or `inf`, for numbers or percentages, are refused instead of accepted.

## Upgrading

`hutch machine upgrade` upgrades the lead, then every worker. Running boxes keep running.

Garbage collection now needs a bucket that supports [conditional deletes (`If-Match`)](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-deletes.html). AWS S3 does. If yours doesn't, `hutch machine gc` says so and deletes nothing; backups and restores still work.
