# Hutch v0.2.2

The TUI does what the CLI does. Review and commit an agent's work, forward its ports, manage machines, and set up a project's template without leaving it. See [the TUI](https://github.com/mouizahmed/hutch/blob/main/docs/tui.md).

## New

- **Git view (`g`).** A box's checkout as the agent sees it: staged, unstaged, untracked and conflicted files, each file's diff, and the task diff against the base branch. Stage and unstage whole files (`a`/`u`) or single hunks (`A`/`U`). Commit what's staged (`c`). Fetch, then pull fast-forward only or push (`f`, `p`, `P`), with pull and push asking first. Looking changes nothing and contacts no remote; a hunk, or a commit whose staged files changed since you saw them, is refused.
- **Ports view (`o`).** What a box listens on, and forwarding a port to this computer (Enter), choosing another local port, or any free one, when it's taken.
- **Machines view (`m`).** Each machine's role, state, version and room, plus adding, removing, changing the lead and upgrading.
- **Action palette (Space).** Every action for the selected project, box, terminal or view, found by typing. An action that doesn't apply says why instead of running.
- **Search (`/`).** Narrows the open project's boxes and terminals by name, agent, branch or machine.
- **Commands as task rows.** A new box, a move or a push runs in the background as a row with its output. A failure stays with its error until `d` dismisses it, and `d` cancels one that's running. A failed or canceled new box gives its prompt back to the next form.
- **Template guidance.** A project's template row shows where the template stands and the one key that takes it on: set up, open the setup agent, confirm the box size, build, snapshot. Until the size is confirmed, `b` and `S` show the project form first, as the CLI does.
- **More of the CLI in the TUI.** Templates, the serial console, logins, `user sync`, showing, editing and checking config, grants, doctor, sizes, the bucket and garbage collection are all in the palette. What asks questions or prints something to read gets the whole terminal and comes back when it ends.

## Fixes

- A `hutch new` that fails or is canceled before the box is on its branch removes the box, instead of leaving one with no repository.
- Canceling a task, or quitting, stops what the command started as well, including on Windows.
- A machine whose hutchd is older than the TUI isn't labelled a worker: a lone machine shows as the lead.

## Upgrading

`hutch machine upgrade` upgrades the lead, then every worker. Running boxes keep running.
