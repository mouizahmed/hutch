# Hutch v0.2.5

Clearer failures when starting agents, accurate worker timestamps, and a way to reset a machine for setup again.

## New

- **Reset a machine.** `hutch machine reset <ssh-host> --yes` permanently deletes its local boxes, snapshots, projects, logins, settings, and identity. It keeps installed runtimes, images, build cache, the storage mount, and the bucket. The daemon is stopped and disabled until `hutch setup <ssh-host>` runs again. Remove a worker first; a lead with enrolled workers must hand over the lead or remove those workers before resetting.

## Fixes

- Starting an agent that's missing from a box reports which agent is missing and how to start a shell. This includes bare `--image base` boxes, which have no agents installed. The box remains available; `--cmd` still runs commands normally.
- Workers save their last-seen time on every heartbeat. Right after a lead restart, before workers reconnect, `hutch doctor` shows a recent time rather than their old connection time.
- `hutch cloud` consistently requires a built project template and gives the setup steps when one is missing. It no longer falls back to a hidden sleeping box named `base`.
- Generated CLI and settings references use LF on every platform, fixing the Windows CI failures after the documentation update.

## Upgrading

Install its CLI and run `hutch machine upgrade` to upgrade the lead and workers. Existing boxes keep their work. Reset is destructive and is only for a machine you explicitly want to clear.
